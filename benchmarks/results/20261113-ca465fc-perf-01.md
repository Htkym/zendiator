# PERF-01 adoption and measured tradeoffs

PERF-01 is adopted by explicit user benefit/tradeoff judgment. The earlier strict
common non-regression gate was **not passed**. The user accepted the ScopeK1 and
warm Send5 benefits with the reverse ResolveSend0 regression, the allocation
tradeoff and the unresolved unchanged-peer differences retained below. Adoption
does not change any measurement classification or claim that the original gate
passed. It does not itself merge a PR or release a package.

The [full-precision numeric evidence](20261113-ca465fc-perf-01.json) contains all
15 pairs in each block. Both measured revisions identify product version 0.6.0:
baseline `8572cda3293ff2bdf288d7220b9bbebf4ccf4db3` and candidate
`ca465fc9373ca7cf2463401f2ed1c2c2ec639b73`. The adopted implementation is that
measured candidate. Version and documentation changes target 0.7.0 separately;
these values are not measurements of a newly versioned 0.7.0 package.

Conditions were SDK 10.0.404, .NET 10.0.14 x64, workstation GC, Release,
affinity mask 1, BenchmarkDotNet 0.15.8, 20 warmups, 12 actual measurements and
one launch per cell on Windows 11 / Intel Core Ultra 7 258V. Requested iteration
time was 500 ms; FirstSend and ColdOuterFailure instead use 16,384 invocations
and unroll factor 1 without enforcing that duration. The JSON records actual
host, source, canonical controls, measured product hashes and report bindings.

Across the 13 unique Zendiator cases, allocation decreases in 5 and is unchanged
in 8 in each block; none increases. The counts exclude the two peer controls.
Three cases improve in both orders: ScopeK1, warm Typed Send5 and ScopeK10.
No Zendiator case regresses in both orders; ResolveSend0 regresses in reverse
only. ScopeK1 meets its <=704 B target at 624 B, 80 B below baseline, but misses
the minimum-allocation effort goal: Immediate remains at 568 B, 56 B lower.

The unchanged Immediate ScopeK10 control regresses by 14.728131% forward and
16.238053% reverse with disjoint intervals. Its cause is unresolved. Selected
saved-child ResolveSend0 and Immediate ScopeK10 paths have equal normalized
managed IL and implementation flags. Selected consumer/product DLL bytes are
stable within each side across the two blocks. These findings do not rule out
indirect changes through enclosing types, metadata, native JIT code or DI/hash
layout, and do not establish a causal explanation for either regression.
The earlier A/A smoke is corrected to **same-source rebuild A/A**: its measured
DLL bytes differ between sides, so it was not a same-binary A/A noise check.

All times below are ns/op. Delta is candidate minus baseline; a negative time delta is a lower observed mean. Only non-overlapping confidence intervals receive an improvement or regression classification. BDN raw confidence Level is 12 throughout; this is an enum value, not 12%.

Across the separate blocks, baseline ResolveSend0 moves from 28.888034 to 25.943838 ns, while candidate moves from 29.962437 to 29.949776 ns. This is a descriptive block-to-block observation, not a pooled estimate, controlled effect or explanation.

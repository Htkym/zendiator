# Release notes — Zendiator 0.1.0

Tag candidate: `v0.1.0`. Package version: `0.1.0`.
Source commit `a1033e9a521b2c22c50b17a0c120fded42093be7` plus the 0.1.0 preparation changes.
`0.1.0` is a `0.x` release: its API is not frozen permanently and may change before `1.0.0`.

## Features

- Typed Send (`SendAsync` overloads for concrete request types; no `IRequest<T>` / `object` generic send API)
- Unit-free void (`IRequest` native void route via `ValueTask`)
- Generic Request (including `new()`-constrained responses)
- Notification / sequential Publish (`PublishAsync`; parallel publish is unsupported)
- Multi-handler dispatch (`IMultiRequest`)
- Sync / ref struct (`ISyncRequest` + `SendSync`)
- Generic-ref (composite `allows ref struct` constraints)
- Stream / Stream Pipeline (`StreamAsync`, lazy `IAsyncEnumerable`, behaviors, cancellation, disposal)
- Generic Stream
- DI-first (`AddZendiator` configuration lambdas; class-mode and assembly-attribute compat routes remain)
- Assembly / legacy compatibility

## Quality

- 251 tests green (10 test projects; no unexplained count change from RC2)

## Performance

Current formal measurements only (BenchmarkDotNet 0.15.8, Release, Throughput, MemoryDiagnoser,
3 launches, 3 warmups / 8 measurements each). Values apply to the measured routes and environment.

Typed Send (synchronously completing handlers, warmed-up scopes):

```text
Scoped:    0 behavior = 21.4 ns / 0 B, 1 = 50.8 ns / 0 B, 3 = 90.6 ns / 0 B, 5 = 140.5 ns / 0 B
Singleton: 0 behavior = 5.1 ns / 0 B,  1 = 12.4 ns / 0 B, 3 = 24.0 ns / 0 B,  5 = 46.0 ns / 0 B
NativeVoid = 22.0 ns / 0 B
Generic Request = 28.6 ns / 24 B (response creation included on both sides)
Scope K=1 (create + resolve + 1 send + dispose) = 113.1 ns / 360 B
Scoped + mediator resolve each call = 54.3 ns / 0 B
Concrete generated type = 22.3 ns / 0 B (no speedup recommendation from call-site type alone)
```

Stream:

```text
sync / 0 behavior / 1024:  Zendiator 17.622 us / 232 B, Direct 12.947 us / 120 B
async / 0 behavior / 1024: Zendiator 648.388 us / 113,959 B, Direct 343.341 us / 360 B
create only: Zendiator 4.407 ns / 40 B, Direct 6.974 ns / 120 B (lazy creation; not whole-dispatch speed)
```

Sync-completing 0-behavior streams allocate 232 B/stream across the measured item counts.
`OPT-stream-async` remains a known performance concern (additional 110.94 B/item vs Direct
under async / 0 behavior / 1024 items). Full per-route tables with medians, deviations,
and GC: [formal measurements](../performance.md). The values above are the current claims.

RC1/Hardening-1 numbers are `HistoricalSuperseded` and are not used as current values.
No overall-fastest, completely-allocation-free, commercial MediatR comparison, all-AOT,
all-generics, or IDE-complete claims are made.

## Installation and migration

Use matching `Zendiator.Abstractions` and `Zendiator` package versions:

```xml
<ItemGroup>
  <PackageReference Include="Zendiator.Abstractions" Version="0.1.0" />
  <PackageReference Include="Zendiator" Version="0.1.0" />
</ItemGroup>
```

The [README](../../README.md) provides the configuration example and project split.
The [MediatR migration guide](../migrating-from-mediatr.md) covers `ValueTask`, native void,
explicit behavior order, typed request APIs and `StreamAsync`.
No new public API or performance optimization was introduced during this release execution phase.

## Artifact provenance

The release workflow builds the tag commit, audits package contents/dependencies/version/source,
freezes SHA256 and source hashes in a manifest, and verifies the same files with consumer, DI and AOT apps.
The publish job downloads those CI artifacts, revalidates the manifest, and pushes the exact files.
It does not repack or use `--skip-duplicate`, and the first push failure stops the job.
GitHub Release attachments and release-execution evidence reference that CI artifact.
Local candidate packages are verification artifacts, not the official publication artifact.

GitHub-hosted execution, OIDC and NuGet ownership are verified at publication time.
No push, tag, GitHub Release or NuGet publish is performed without explicit user approval.

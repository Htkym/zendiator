# 0.7.0 release notes

Status: Unreleased. This describes the next development version; it is not a
published package announcement.

## Route-local capture for synchronous Before hooks

Eligible closed `SendAsync` routes with only synchronous Before hooks now resolve
their borrowed reference-type receivers together on the first Send and reuse the
successful set for that route. The handler and hooks must include at least two
distinct receiver types and use no Zendiator session/factory contract or wrapper.
Open generic route definitions, value receivers, handler-only routes and other
unsupported shapes retain their existing capture behavior.

Any required receiver construction occurs before the first Hook callback.
An outer Hook failure can therefore leave already constructed inner Hooks or the
handler unused. Dependency construction failures occur before Hook callbacks
begin; failed acquisition is not cached as a successful set.

This changes construction timing and Transient identity. Separate routes can
capture different instances of the same Transient receiver type. A receiver used
only through route-local sets has no separate per-type Mediator capture;
resolution through the Mediator's explicit `IServiceProvider` interface delegates
to the original provider. Types still used by a direct route retain that route's
per-type capture. Scoped and Singleton identity continues to follow DI.

Explicit `EagerDependencies` preserves the affected synchronous-Before-only
route's direct capture, injected instances and acquisition timing. It does not
make previously rejected asynchronous Hook, session or open generic shapes
eligible.

## Guarded Stream scope initialization

The guarded consumer root now performs the dedicated initial scope probe when its
first move starts initialization. Inner deferred opening and normal reopening no
longer repeat that initial probe. StreamBefore retains its checks before later
Before callbacks and before opening the route, including after a pending callback.
Native DI activation, ownership and disposal remain unchanged.

The existing flat public iterator path still acquires its input at
`GetAsyncEnumerator` when neither token can be canceled and no Before, hooks,
middleware or owned session is present. This change does not broaden that path or
change public signatures.

## Migration

Review constructor side effects and failures before upgrading. Register receivers
as Scoped or Singleton when separate routes must share their identity. Use
generated composition registration; a custom provider must also resolve the
generated route set. Its name and layout are implementation details.

Keep the DI scope alive through dispatch and cleanup, and consume each
`ValueTask` once. The synchronous-Before-only path still returns the handler's
original `ValueTask` and can throw synchronously during the call. Native DI owns
receiver construction and disposal, including unused receivers.

`ValidateOnBuild` can inspect registered route-set constructor graphs; it does
not validate every dispatch dependency, arbitrary DI factory body or open generic
closure. Exercise the application's routes with `ValidateScopes` enabled. See
the [capture and lifetime guide](../getting-started-0.5.0.md#route-local-capture-for-asynchronous-hooks)
for the full contract.

For Streams, retain the original DI scope through enumeration and awaited
cleanup, including HTTP serialization. Deferred inner opening or reopening is
not a new scope boundary. Do not rely on a later inner probe to detect premature
scope disposal: an already captured receiver may be reused without a new native
resolution. See the [input and lifetime guide](../streaming-iterators.md#choose-an-input-contract).

## Route-capture verification and performance decision

The implementation candidate passed the full solution tests, package checks and
the existing win-x64 NativeAOT package-consumer execution, including dependency-set
construction, reuse, native DI disposal and `ValidateOnBuild` checks when building
the DI container. Other RIDs are
not established by that result. JIT timing does not establish an AOT speed gain.

The controlled forward and reverse comparisons improved ScopeK1 and warm
five-hook Send in both orders. The reverse zero-hook ResolveSend comparison
regressed, while an unchanged Immediate ScopeK10 control also differed in both
orders. The cause of those differences remains unresolved. Adoption accepts this
recorded non-regression exception; it does not claim that every prior gate passed.
The timings were recorded from the implementation candidate before the version
and documentation update. Consult the [measurement conditions](../../benchmarks/performance-plan/README.md)
when interpreting or reproducing the comparison. The [full forward/reverse results
and adoption decision](../../benchmarks/results/20261113-ca465fc-perf-01.md)
retain every compared case, confidence interval, allocation and the accepted
non-regression exception.

## Stream scope-check verification and performance decision

The scope-check change passed the targeted Generator contracts and Stream
allocation check, together with the implementation candidate's full solution,
package and managed/native-consumer CI. An additional four-case normal-controller
comparison reproduced the five-stage synchronous 16-item EarlyBreak improvement
in both orders, at about 3-4%, with 1,016 B/op unchanged. This result does not
establish an asynchronous-stream or general performance gain.

Zero-stage Full varied by order: one direction regressed by about 5%, while the
other improved by about 2%. The earlier 66% observation did not recur. Earlier
common/typed regressions and asynchronous +1 B observations remain in the
record. Adoption accepts this tradeoff; it does not mark the original strict
non-regression or allocation gates passed, or identify an environmental cause.
The [PERF-02a comparison and adoption decision](https://github.com/Htkym/zendiator/pull/24)
records the conditions, separate experiments and remaining uncertainty.

# Zendiator 0.2.0 リリースノート

[English](0.2.0-release-notes.md)

Zendiator 0.2.0 は、標準 DI と依存オブジェクトの遅延取得を使う実行経路に統一し、
Source Generator の増分生成と設計資料を改善したリリースです。
V1 前のプレビュー版であり、依存オブジェクトの再利用方法に破壊的変更があります。
更新前に以下の注意点を確認してください。

## 破壊的変更: 依存オブジェクトの再利用

各 Mediator は、Handler・Behavior のサービス型ごとに最初に取得したインスタンスを保持します。
Transient 登録も対象です。同じ Mediator で再度送信したりリトライしたりする場合、
取得済みのインスタンスを再利用し、毎回新しいものを取得するわけではありません。

生成と破棄は引き続き DI が担当します。Scoped・Singleton の共有範囲は DI の登録に従います。
Pipeline が途中で処理を終了した場合、まだ到達していない後続の依存オブジェクトは構築しません。
既定の登録ライフタイムは Scoped のままです。

更新時には、コンストラクターの実行回数、呼び出し間の状態保持、並行実行、破棄の担当を確認してください。
送信やストリーム列挙が終わるまでスコープを維持してください。
`ValidateOnBuild` を使っていても、遅延取得する依存関係の検証は初回の送信まで遅れる場合があります。
詳細は[構築と実行時のライフタイム](../optimized-dispatch.md)を参照してください。

## 構築方法

標準の導入方法では、登録は次の呼び出しだけで済みます。

```csharp
using Zendiator.DependencyInjection;

services.AddZendiator();
```

通常の `BuildServiceProvider()` または Host のビルダーを使用します。
専用 Provider・Factory、実行モードの選択、追加の初期化呼び出しは不要です。
構成ラムダは、アセンブリ、Behavior、名前空間などを指定する場合だけ使用します。
アプリケーションの登録をまとめるラッパーメソッドも任意です。

## 実装とドキュメント

- 依存オブジェクトを遅延取得する単一の実行経路と、ジェネリックな構造体の継続処理を使用します。
- 生成するストリーム処理で、列挙の開始処理と通常の `MoveNextAsync` を分離しました。
- Generator の一回の解析内で、インターフェイスの走査結果と型名を再利用します。
- Roslyn の解析結果を、内容で比較できる不変の出力モデルへ変換します。
  モデルが等しければテンプレート展開を省略し、インターセプターの位置変更は別に扱います。
- ソースを責務ごとに整理しました。生成テンプレートには生文字列リテラルを使い、
  多数の無関係な引数の代わりに意味のある単位のモデルを渡します。
- 日英の README と MediatR 移行ガイドを更新しました。
  設計・保守方針を参照するための [Constitution](../../Constitution.ja.md) を追加しました。

Compilation が変わると意味解析は再実行します。
型単位の増分解析や、無関係な編集では Generator の処理が一切発生しないことを保証するものではありません。

## インストールと更新

```shell
dotnet add package Zendiator --version 0.2.0
```

`Zendiator` は Generator を含み、`Zendiator.Abstractions` に依存します。
契約だけを定義するプロジェクトでは `Zendiator.Abstractions` だけを参照できます。
両パッケージを明示的に参照している場合は、バージョンをそろえて更新してください。
利用プロジェクトを再ビルドし、実行コードを再生成してください。

[README](../../README.ja.md)、[MediatR 移行ガイド](../migrating-from-mediatr.ja.md)、
[制限事項](known-limitations.md)も参照してください。
Native AOT の検証対象は win-x64 です。オープンジェネリックの DI Handler を値型で閉じる経路には制限があります。

## 検証と性能情報の範囲

リリース時には、Release ビルドとテスト、書式、パッケージ内容、サンプル、
独立した PackageReference 利用プロジェクト、win-x64 の Native AOT マトリクスを確認します。
ローカルでの準備は、最終タグのコミットに対する検証の代わりにはなりません。
公開ワークフローではパッケージを検証し、その同じ成果物を配布します。

0.2.0 では、他ライブラリとの新しい正式な性能順位は公表しません。
[0.1.0 の性能記録](../performance.md)は測定時の実装に対するものであり、
今回の依存オブジェクトを保持する設計の測定値ではありません。
すべての経路とライフタイムで最速、または割り当てがないという主張はしません。

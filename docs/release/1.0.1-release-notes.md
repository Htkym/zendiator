# Zendiator 1.0.1

Zendiator applications target .NET 10 and C# 14. To upgrade from 1.0.0, update `Zendiator`, any direct reference to `Zendiator.Abstractions`, and the optional `Zendiator.CodeFixes` package to 1.0.1. Restore and rebuild the projects that use generated mediators. [Upgrade guide](../upgrading.md) · [日本語の更新ガイド](../upgrading.ja.md)

## Asynchronous streams

Stream cursors now reuse one field for the enumeration token and the effective cancellation token. For custom cursors that suspend on every item, the existing `[GeneratePooledProducer]` attribute also lets the asynchronous move helper reuse its state machine. The representative benchmark now opts into this feature and still executes one `Task.Yield()` per item. Reading all 1,024 items through five middleware stages allocated 1,586 B in both execution orders. The 1.0.0 control on the same machine used the original input cursor without the attribute and allocated 116,322 B. [Pooled producer example](../pooled-producer.md) · [Measurements and conditions](../../benchmarks/README.md)

## Scoped dependency caching

The default for `ZendiatorCompositionAttribute.ClosedServiceCache` is now `ClosedServiceCacheMode.Auto`. When a composition has open generic services, more than two closed dependency types and no eager dependencies, the mediator stores the first resolved closed service directly and uses the existing cache for the others. A five-stage Send in a new scope allocated 560 B per operation, down from 624 B. Applications can select `Inline` to reserve a field per closed service or `LazyBlocks` to allocate slots in groups. [Dependency lifetimes and cache modes](known-limitations.md)

## Code fixes

The `Zendiator.CodeFixes` NuGet package now displays the same icon as the runtime and contracts packages. [Code fix installation](../../src/Zendiator.CodeFixes/README.md)

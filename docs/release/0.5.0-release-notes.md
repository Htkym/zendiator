# Zendiator 0.5.0

0.5.0 changes the registration, handler and Stream APIs. Recompile consumers and
migrate from 0.4.0 using the [getting-started guide](../getting-started-0.5.0.md).
The library requires .NET 10 and C# 14; pre-1.0 APIs may change.

## Packages

Use matching versions of `Zendiator` and `Zendiator.Abstractions`. `Zendiator`
includes the source generator and depends on Abstractions. A contracts-only
project can reference Abstractions alone.

```shell
dotnet add package Zendiator --version 0.5.0
```

Before 0.5.0 is published to NuGet.org, use matching locally built packages from
your package feed. Install the optional `Zendiator.CodeFixes` package separately
at the same version with `PrivateAssets="all"`. It is not a runtime dependency.

## Registration and migration

- Mark selected handlers with `[ZendiatorHandler]` and register them explicitly
  through `Handlers`. Named compositions use `[ZendiatorComposition]`.
- Declare hooks and wrappers in an ordered `Pipeline`; type-changing Stream
  pipelines declare their final item type with `StreamPipeline`. Eligible
  handler-only Send routes can omit an empty pipeline; a zero-stage Stream route
  declares one explicitly.
- Preserve wrapper retry, caching and continuation behavior when migrating.
  Arbitrary wrapper bodies are not automatically rewritten into hooks.
- Replace the 0.4.0 Stream handler contract with an `IStreamHandler` returning
  `IAsyncEnumerable<T>`, or an `IStreamSourceHandler` opening a named cursor.
  `StreamAsync` returns a standard asynchronous enumerable.

## Ownership and completion

Generated registration uses a Scoped `IZendiator` and Transient defaults for
handlers, hooks and session factories. A Mediator reuses captured dependencies;
this includes Transients. Eligible asynchronous Hook routes acquire a route-local
set before the first Hook, including dependencies unused after an outer failure.
Constructor timing and Transient identity can therefore differ between routes.
DI retains activation and disposal ownership. Keep the scope alive until dispatch,
enumeration and cleanup finish, and consume each returned `ValueTask` once.

Eligible plain `SendAsync` routes return the handler's original `ValueTask`.
Dependency resolution and synchronous callbacks can throw during the call, before
an operation is returned. Put both the call and its await inside the `try` block.
Do not rely on internal helpers to isolate ambient state or return to a UI context.

Guarded Stream paths acquire input on the first move and reject overlapping
operations. Flat iterator routes without Before, hooks, middleware or owned
sessions and with noncancelable API and enumeration tokens acquire input at
`GetAsyncEnumerator`; the producer's contract applies, and the consumer must await
disposal after EOF or failure too. Use `await foreach` and forward actual
cancellation tokens. Read the [input and lifetime guide](../streaming-iterators.md).

`StreamSource(...).ConsumeAsync(...)` is a separate sequential terminal, not an
`IAsyncEnumerable`. Value-type sinks are copied; put accumulated results in shared
reference state. The terminal does not promise lower time or allocation.

## Storage, diagnostics and IDE fixes

Closed dependency slots are inline by default. Select
`ClosedServiceCacheMode.LazyBlocks` explicitly for workloads that benefit from it;
it can cost more for dense access or warm reuse. Open generic capture uses a small
cache before dictionary promotion. Neither layout is universally faster.

Configuration diagnostics reject unsupported or ambiguous registrations; suppressing
a diagnostic does not enable the route. The separately installed optional CodeFix can
add a missing handler marker and supports document-scoped Fix All in current Visual
Studio. It does not migrate pipeline ordering, lifetimes or wrapper semantics.

## Performance and limitations

The [README](../../README.md#performance) compares selected workloads from the
measured 0.5.0 candidate. Some synchronous and repeated-call cases have lower time
or allocation than peers, while new-scope, short-circuit and early-termination
cases include unfavorable results. Asynchronous Stream and Relay workloads can
allocate substantially more; the 0-behavior asynchronous Stream and 5-stage
asynchronous Relay cases are unfavorable in time as well. These observations do
not establish a universal lead or a controlled before/after improvement.

Native AOT package-consumer verification targets win-x64. Open-generic DI handlers
closed over value types remain a limitation; other RIDs are unverified. Runtime-
object request/Stream dispatch and parallel Publish remain unsupported. See
[known limitations](known-limitations.md) for ownership, ambient context, retained
references and asynchronous workload boundaries before deploying.

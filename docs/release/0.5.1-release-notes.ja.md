# Zendiator 0.5.1

0.5.1 は、0.5.0 の Mediator 登録・配送・Stream の契約を維持し、実験的な producer の opt-in と Generator の修正を追加します。既存アプリケーションで opt-in は必須ではありません。利用側は各 package の版を揃えて再ビルドしてください。.NET 10 と C# 14 が引き続き必要です。0.4.0 からの移行には、[0.5.0 のガイド](../getting-started-0.5.0.ja.md)を参照してください。

## Package

```shell
dotnet add package Zendiator --version 0.5.1
```

`Zendiator` と `Zendiator.Abstractions` は同じ版を使います。Source Generator は `Zendiator` に含まれます。任意の `Zendiator.CodeFixes` は、別途 0.5.1 を `PrivateAssets="all"` 付きで導入してください。NuGet.org で 0.5.1 が公開されるまでは、同じ版のローカルビルド済み package を使ってください。

## 変更点

- 条件を満たす sealed Send wrapper を、generic interface 経由ではなく直接呼び出します。それ以外の binding は従来の interface 呼び出しを維持します。
- `[GeneratePooledProducer]` による実験的な明示 opt-in を追加しました。対象は、トップレベルの非 generic partial class にある、対応する private・引数なしの `async ValueTask<bool>` helper です。Pooling builder を使う helper を生成し、対応する明示的な source 呼び出しを置き換えます。cursor instance 自体は pool 化しません。
- partial producer helper の実装と、そこから呼び出す source helper の経路を生成前に検証します。未対応の宣言・本体・呼び出しには診断を出します。
- 同期 Before のキャンセル、null とキャンセルの優先順位、同期例外、再入、型付きの closed-generic composition に回帰テストを追加しました。

## Producer の opt-in の範囲

導入前に [producer のガイド](../design/pooled-producer-interceptors.md)を確認してください。返された `ValueTask` は必ず 1 回だけ消費します。reflection や未対応の呼び出しは pool 化されません。生成名や例外の stack trace は変わることがあります。通常の `async IAsyncEnumerable<T>` iterator や、暗黙の `await foreach` 呼び出しは変換しません。

属性を付けなければ、既存の Handler・producer・consumer の動作は変わりません。対応する source の構文は意図的に限定しています。診断の抑制で未対応のメソッドを利用可能にはできません。

## 性能と制約

producer のガイドには、.NET 10.0.14/Linux 上で、1,024 item の非同期 Native Stream0 と Relay5 を 3 組ずつ比較した結果があります。この条件では opt-in により 1 操作あたり 114,688 bytes 減り、測定した時間の中央値も短くなりました。比較対象内の順位は上がっていません。同期 Stream0 は 3 組すべてで遅く、同期 Relay5 の時間は増減が混在しました。一般的な高速化や無退行を保証する結果ではありません。README の 0.5.0 比較は別の過去測定です。

未採用の Stream completion・早期停止・Relay layout の試作は含みません。interceptor の明示的な null guard も維持しています。

Native AOT の package 検証対象は win-x64 です。値型で閉じた open-generic DI Handler の制約は残り、ほかの RID はその検証の対象外です。DI scope の維持、単回消費、Stream の逐次利用など、[既存の所有権と実行上の制約](known-limitations.md)も引き続き適用されます。

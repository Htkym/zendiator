# Zendiator 1.0.0-rc.1

This release candidate targets .NET 10 and C# 14. Upgrade `Zendiator` and any explicit `Zendiator.Abstractions` references together to `1.0.0-rc.1`, then rebuild the application. If you use the optional `Zendiator.CodeFixes` package, select the matching version. The supported surface includes the documented registration APIs and generated dispatch methods used by applications. From 1.0.0 onward, incompatible changes to those APIs or their documented behavior require a new major version. [Compatibility and lifetime policy](known-limitations.md)

## Registration

Use `services.AddZendiator<App>(...)` for normal registration. A conditional call such as `getServices()?.AddZendiator<App>(...)` evaluates the receiver once and skips registration when it returns null. A fully qualified static call to the extension method is also supported.

With the package analyzer enabled, converting the registration method itself to a delegate produces ZEN0020. The generator needs the call site to connect the configuration to its generated implementation. If a host expects a delegate, put the direct call and its configuration inside a method or lambda and pass that instead. [Registration diagnostics](../diagnostics/configuration.md)

## Existing applications

- Keep the same DI scope through dispatch and Stream disposal. The mediator reuses resolved receivers, including Transients. Eligible closed asynchronous Send hook routes acquire their receiver set before running the first hook. Constructors may therefore run for downstream stages that never execute. These are the existing 0.7.0 lifetime rules. [DI migration details](0.7.0-release-notes.md)
- Notifications use sequential subscribers and the assembly-based registration API. The README shows a single generated mediator sending a request and publishing a notification. Named compositions continue to describe Send and Stream routes. [Getting started](../../README.md)
- Stream middleware can return the upstream cursor, return an operation stored in a local variable, or wrap the cursor. Forwarding uses runtime cursor identity and matching tokens. When a middleware returns a decorator, its item access and disposal remain part of enumeration. [Stream ownership](../streaming-iterators.md#forwarding-or-decorating-a-cursor)
- The opt-in `[GeneratePooledProducer]` source transformation is experimental. Its supported method bodies and diagnostics may change in 1.x. [Experimental feature scope](../design/pooled-producer-interceptors.md)

## Compatibility checks

The [release pack script](../../scripts/Pack-CompatibleRelease.ps1) builds baseline packages from the preceding release tag, compares the runtime and contracts with the SDK package validator, and exercises that tag's sample against both versions. It also runs the previously compiled host against the regenerated facade and the previously compiled host and handlers against the candidate runtime. For this candidate the baseline is `v0.7.0`. The RC tag becomes available as a baseline for subsequent releases.

The recorded [14-workload performance measurements](../../benchmarks/results/0d53c53-representative.ja.md) apply to implementation commit `0d53c53`. They cover the Stream ownership change and predate the RC's registration and packaging changes.

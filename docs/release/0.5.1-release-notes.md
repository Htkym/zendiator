# Zendiator 0.5.1

0.5.1 keeps the 0.5.0 mediator registration, dispatch and Stream contracts. It adds
an experimental producer opt-in and generator fixes. Existing applications do not
need to opt in. Rebuild consumers with matching package versions. .NET 10 and
C# 14 remain required; migration from 0.4.0 still follows the
[0.5.0 guide](../getting-started-0.5.0.md).

## Packages

```shell
dotnet add package Zendiator --version 0.5.1
```

Use matching versions of `Zendiator` and `Zendiator.Abstractions`. The source
generator is included in `Zendiator`. Install the optional `Zendiator.CodeFixes`
package separately at 0.5.1 with `PrivateAssets="all"`.
Until 0.5.1 is available on NuGet.org, use matching locally built packages.

## Changes

- Eligible sealed Send wrappers use direct calls instead of generic interface
  dispatch. Other bindings retain the interface fallback.
- `[GeneratePooledProducer]` enables an experimental source transformation for
  supported private, parameterless `async ValueTask<bool>` helpers in top-level,
  non-generic partial classes. The generator creates a pooled-builder helper and
  intercepts supported explicit source calls. The cursor instance is not pooled.
- Partial producer helper implementations are validated before generation,
  including their source-helper graph. Unsupported declarations, bodies or call
  sites produce diagnostics rather than silently promising pooling.
- Regression coverage includes synchronous Before cancellation, null-versus-
  cancellation priority, synchronous exceptions, reentrancy and typed
  closed-generic composition.

## Producer opt-in boundaries

Read the [producer guide](../design/pooled-producer-interceptors.md) before using
`[GeneratePooledProducer]`. Each returned `ValueTask` must be consumed exactly
once. Reflection and unsupported call sites do not gain pooling. Generated names
and exception stack traces can differ. The feature does not transform ordinary
`async IAsyncEnumerable<T>` iterators or implicit `await foreach` calls.

The marker is optional. Existing handler, producer and consumer behavior remains
unchanged when it is not used. The supported source grammar is intentionally
restricted; do not suppress diagnostics to force unsupported methods through.

## Performance and limitations

The producer guide records three paired rounds of representative 1,024-item
asynchronous Native Stream0 and Relay5 workloads on .NET 10.0.14/Linux. The opt-in
saved 114,688 bytes per operation in those cases and reduced their measured
median time. Competitive median ranks did not improve. Synchronous Stream0 was
slower in all three pairs, and synchronous Relay5 had mixed time directions.
These results do not establish universal improvement or absence of regression.
The README's historical 0.5.0 comparison remains a separate measurement.

Unadopted Stream completion, early-stop and Relay-layout experiments are not part
of this release. The interceptor's explicit null guard remains in place.

Native AOT package validation targets win-x64. Open-generic DI handlers closed
over value types remain a limitation; other RIDs are not covered by that gate.
The [existing ownership and execution limitations](known-limitations.md) still
apply, including DI scope lifetime, single consumption and sequential Stream use.

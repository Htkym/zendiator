# WP08：SendAsync wrapperの軽量完了境界

## 結論

採用。元のShort fixtureで時間比は3対とも1未満となり、比率の中央値から計算した処理時間の短縮率は13.5843%だった。割り当ては0 B/opのままである。2026-11-08のユーザー指示に従い、小さな改善も採用する。合意済みperf/plan branchへ統合し、mainへのmergeやreleaseはしていない。

この値は、対象fixtureのSendAsyncが同期完了するwrapper経路の結果であり、アプリ全体の短縮率ではない。Hの対照routeは生成sourceがbyte単位で同じだった。Hの時間・割り当ての変動を、この変更の効果として数えない。

## 変更と契約

対象を、参照型wrapperだけで構成され、Hook、session、factory、open genericを含まない、戻り値付きSendAsyncの該当regionに限定した。小さな生成stateをAsyncValueTaskMethodBuilder.Startで開始し、同期成功を直接完了する。pendingとfaultはasync helperで一度だけ消費し、例外を呼び出し時のthrowへ変えない。

AsyncLocal、culture、SynchronizationContextの変更が呼び出し側へ漏れないこと、例外identity、OperationCanceledExceptionのCanceled状態、custom ValueTask sourceのGetResult一回消費を確認した。mutable struct wrapperは既存のboxed receiver経路へ残す。対象外のHook、factory、sessionなども従来経路を維持する。

既存関連38試験と境界14試験が成功した。独立コードレビューでblocking findingはなく、split/mixed/SendAll、型名変換とfallbackも確認した。統合後の最終全体検証は、最終概要にまとめる。

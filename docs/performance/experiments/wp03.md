# WP03 実験結果

## 結論

採否は保留する。属性なしの分離だけで、closed service cache の解決処理が Tier1 の caller から別 helper に残った。`NoInlining` や `AggressiveInlining` を追加する根拠は得られていない。正式な時間比較と B/op 比較は行っていない。

L3 の warm caller では、baseline も cache hit の load/test を inline 化していた。候補は cold 部分の code size を減らすが、warm caller の prolog と cache hit の命令数はほぼ同じだった。code size の差を速度改善とは扱わない。

## 比較対象と変更

- Baseline SHA: `7c69f2a7408a68f36cf25abc3c6ac74ef00c5054`
- Candidate SHA: `3bafd184ed662b357430a2409a7c017cfb1d513b`
- 変更: `CanonicalClosedServiceCacheEmitter.cs` のみ、3 行追加、1 行削除。
- `Service_*` の Volatile read と cache hit を残し、既存の DI 解決、null 判定、CAS を nullable な `Resolve_*` に移した。LazyBlocks では読取済み block を引数として渡す。
- Required の例外、optional GetService の null、再試行、CAS winner、box identity、native DI の活性化・破棄と scope 契約は変更しない。cache、delegate、eager resolve、属性は追加していない。

JIT 比較には、回収済みの元 `Competitive.ShortCircuit.ZendiatorShortCircuit.WarmDispatch` を使った。fixture と製品は SDK 10.0.403、runtime 10.0.14、DI 10.0.12。隔離した診断 probe は net10.0 を対象とし、SDK 11.0.100-rc.3 でビルドした。probe と fixture はともに runtime 10.0.14 で実行した。

## JIT の観測

baseline と候補を別 process で実行し、それぞれ warm dispatch と standalone getter を 120,000 回呼んだ。12 batch の間に 100 ms 待機した。時間の集計と順位判定は行っていない。

診断設定は `DOTNET_TieredCompilation=1`、`DOTNET_TieredPGO=1`、`DOTNET_TC_CallCountingDelayMs=0`、`DOTNET_TC_CallCountThreshold=10`。`Required_* Service_* Resolve_* MoveNext` を逆アセンブルし、Tier0 ではなく Tier1 の出力を比較した。

- standalone Service: 129 bytes → 16 bytes。候補は load/test/ret と、miss 時の Resolve への tail jump になった。
- standalone Required: 229 bytes → 140 bytes。
- L3 の outer `ExecuteRegion0.MoveNext`: 713 bytes → 622 bytes。

baseline の caller には `IServiceProvider.GetService`、cast、CAS が inline 化されていた。候補の caller には cold helper 呼び出しが残り、同じ処理の重複が減った。属性を追加する比較は行っていない。cold helper は初回 resolve のみで呼ばれ、この診断では Tier0 のままだった。

- CachePolicy: 63/63 件合格、失敗・skip は 0 件。
- 関連 generator test: 35/35 件合格、失敗・skip は 0 件。Inline/LazyBlocks、CAS、null・例外後の再試行、再入、mutable box、DI ownership と scope の既存テストを使用した。実行時間は 4 分 48 秒。
- 元 ShortCircuit fixture: Release build と semantic gate が成功。archive に Git 情報がないため SourceLink 関連の既知の警告が 4 件出た。compiler error は 0 件。
- 変更ファイルの whitespace format 検証と `git diff --check` は成功。

新しい shape test は追加していない。全 solution、AOT、正式な L3/L4 時間・B/op 比較はこの実験では未実行。

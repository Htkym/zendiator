# WP04 実験結果

## 結論

任意の generic struct upstream 契約を持つ現候補 `998abae44668e374b3d8119f385be9abe133b390` は、**保留・非統合**とする。事前に凍結した 3% 基準の強制棄却条件には該当しないが、時間保護は未証明である。5 段の feature 比較では約 200 B/op の削減が再現し、0 段の割り当ては変わらなかった。一方、全 round の時間が保護されたとは確認できない。

feature の成立 speed / material regression / all3slower はいずれも 0 件。default protection は Stream0.Full sync だけが speed 条件を満たし、material regression / all3slower は 0 件だった。この default control の改善を struct port の効果や製品コードへの因果帰属には算入しない。allocation-only の all3slower による強制非採用条件も該当 0 件である。

「全ケースの比率中央値が 1.03 以下」と「全 round の時間保護が証明された」は区別する。大きな単 round 差、round 間 drift、CV を隠さず、良いケースとの相殺、最良 round の選択、許容幅の拡大、任意の再測定は行わない。原集計の `pending-independent-review` は作成時の記録として保全し、独立レビュー後の採用判断を別の [decision](wp04-decision.json) に残した。candidate は local の未公開試作であり、製品統合、既定変更、push、release はしていない。

## 凍結基準と不確実性

凍結 policy は、比率中央値 > 1.03 または全 3 比率 > 1.03 を material regression とし、全 3 比率 < 1 かつ中央値 < 0.97 の場合だけ speed 成立とする。全 3 比率 > 1 なら、割り当てだけが減っても時間保護未証明として採用しない。CV > 5% の noisy case を除外せず、3% 幅も広げない。

- feature Stream5.EarlyBreak sync は round 3 が **+43.2259%**、右側の round mean の幅が **59.96%**。全 median が 1.03 以下でも、この round の悪化は消えない。
- default Stream5.Full sync は round 2 が **+45.6326%**、右側の round mean の幅が **45.42%**。speed 条件を満たした default Stream0.Full sync で相殺しない。
- BDN 保持値の最大 CV は feature 左 / 右が 7.605% / 8.785%、default が 10.341% / 9.911%。feature の noisy case は Stream0 early async、Stream5 early sync の右側、Stream5 early async。default は Stream0 early async の右側と Stream5 early async にある。全 round の CV と drift は CSV/summary に残す。
- Relay sync の左側中央値 / 初期 baseline は feature 0.679410、default 0.692546。初期 baseline からの大きな drift は候補の効果と断定せず、同 campaign 内の pair と分けて記録した。

強制棄却条件に未該当という数値分類と、十分な時間保護が示されたという判断は同義ではない。現候補は保留し、約 200 B/op の削減だけでは統合しない。競合首位、他 runtime、AOT 時間、未測定仮説の実現は主張しない。

# Generated Route services and Stream ownership

The public entry remains the generated `IZendiator` / `Zendiator`: callers send through `Send`, `SendAsync`, `SendAll`, `SendAllAsync`, and `StreamAsync`, or consume a typed plan through `StreamSource`. No request-owned or Immediate-style dispatch API is introduced. Generated call-site interceptors are an implementation detail of those Mediator calls.

## Generated execution

| Path | Implementation |
|---|---|
| Plain SendAsync | Zero-stage and synchronous-Before-only routes without factories or After/Exception/Finally callbacks return the handler's original ValueTask from an ordinary method. Routes with other callbacks, wrappers, or sessions retain their orchestration. |
| Shared dependencies | Route bodies and dependency accessors live directly in the partial Mediator. Closed dependencies use inline fields by default at every composition size. The composition marker can explicitly select typed lazy blocks of up to 16 dependencies. Value-type receivers retain the provider's original object box. Open definitions share a small closed-type cache that promotes to a dictionary. No resolver object or lifetime policy is constructed. |
| Call-site static dispatch | A targeted syntax provider binds Mediator calls and emits an independent interceptor per accepted location. A generated sealed receiver is called directly; other implementations of `IZendiator` receive the original interface call. |

Construction stores the exact provider passed to the Mediator without resolving user stages. Per-dependency acquisition remains deferred until a stage is reached, except for eligible closed asynchronous Hook routes: their route-local set acquires all receivers before the first Hook, after the initial cancellation check inside the async execution boundary. A construction failure occurs before Hook callbacks begin; unused downstream receivers may already be constructed. See the [route-local capture contract](../getting-started-0.5.0.md#route-local-capture-for-asynchronous-hooks) for eligibility and Transient identity. Direct construction does not require a generated policy registration. The Mediator explicitly implements `IServiceProvider`; its per-type accessors can capture a different Transient instance from a route-local set. This does not introduce a separate dispatch entrance.

Call-site dispatch accepts named reference-type receivers. Calls through type parameters or value types retain their original constrained dispatch, so a mutable struct implementation is not boxed into a different receiver. Generated signatures preserve assembly-specific extern alias paths, including generic arguments and constraints.

The canonical namespace reserves the generated `IZendiator` and `Zendiator` identities: configuration rejects existing source declarations, including partial declarations, before canonical emission. Extensions of these reserved types by another generator are outside this API ownership contract. The R3 API projection includes all public entries emitted for these types: selected Send routes, mixed Stream routes, and standalone public Stream routes. A mixed composition is accepted or rejected as a whole; its constructor cannot retain a rejected route. Legacy generation uses its separate API family, and a deliberate same-identity namespace collision already conflicts with its nonpartial interface and constructor.

## Lifetime and initialization contract

Generated registration uses one Scoped descriptor, `IZendiator -> Zendiator`, and Transient defaults for user handlers, hooks, and session factories. There is no concrete Mediator descriptor or interface alias factory. Register overrides before `AddZendiator`; TryAdd preserves them. An entry lifetime override must target `IZendiator`. Registering only the concrete type no longer changes the interface entry. Composition fingerprint validation remains in place.

Per-dependency accessors capture the first published successful native result for each dependency type, including Transient and implementation-factory registrations. Stages and routes using that accessor reuse the object. Eligible asynchronous Hook routes instead publish and reuse a route-local set; separate sets and explicit per-type accessors can capture different Transients. Native Scoped and Singleton identity still follows DI. Closed reference dependencies use `T?` storage and `T`/`T?` accessors; the native object-to-T cast occurs on cold resolution. Value-type handlers, hooks and factories keep object storage and object-returning resolution so calls through their contract interfaces preserve the provider's original box. Open generic dependencies share a closed-type key within that Mediator. A directly resolved Transient or another manually constructed Mediator may obtain a different object. A captured session factory is reused, while its session creation and owned/borrowed cleanup still occur per operation.

Native DI owns activation, Scoped synchronization, and disposal. The generated cache adds no lock around constructors or factories. Competing first callers may activate several Transients; callers whose own resolution succeeds with a nonnull value use the same cold CompareExchange publication winner. This also preserves a winner published by a reentrant dispatch. Losing objects remain DI-owned and are never disposed by the Mediator. A native resolution failure still propagates its original exception even if another caller publishes a winner; a null result produces the Required accessor's missing-service error. Neither failure is captured. A later call reads an existing winner or retries resolution. Closed-slot warm hits use Volatile.Read, with zero generated publication CAS operations and no native liveness probe.

Slots and maps belong to the Mediator instance, with no cross-provider static state. A Singleton entry retains its root provider; resolving an overridden Scoped dependency therefore fails lazily at the dispatch stage under ValidateScopes. A Scoped entry retains its scope provider. A forwarding custom provider remains the authority for each first successful activation; cache hits do not call it again.

Per-dependency accessors share one slot per dependency across routes. Eligible asynchronous Hook routes add route-local set slots and do not populate the set receivers through those per-type accessors. `ZendiatorCompositionAttribute.ClosedServiceCache` defaults to `ClosedServiceCacheMode.Inline`; explicit `LazyBlocks` uses blocks even for a small composition, and emits none if there are no closed dependencies. Undefined values reject the composition with ZEN0035. Selection happens during generation and adds no Send runtime policy branch. A block is published only after a nonnull native resolution; its other slots remain unresolved. Sparse use can retain fewer empty slots, while dense use adds block headers and references, and warm access adds a block read. Open generic caches independently keep up to four closed-type entries before atomically publishing a populated dictionary. Published instances survive promotion; native failures and null results remain retryable. These storage choices do not promise shorter dispatch times. See the [storage choice and measured tradeoffs](../getting-started-0.5.0.md#closed-dependency-storage).

The Mediator does not own its provider or borrowed dependencies and does not register for disposal tracking. Keep the caller's scope alive until all sends and enumeration have completed. Using a captured Mediator after scope disposal, or disposing its scope while an operation is pending and then resuming it, is unsupported. Removal of the hit probe intentionally removes the previous generated rejection guarantee; it does not guarantee successful use after disposal.

## Completion and context

Public entry argument guards remain. Plain SendAsync checks cancellation and runs dependency resolution, synchronous Before callbacks, and the handler call directly. A synchronous failure, including cancellation, throws synchronously. Synchronous prefix changes to AsyncLocal, CultureInfo, or SynchronizationContext are visible to the caller. This is an intentional change from the former builder Start boundary.

Plain SendAsync returns the original ValueTask without checking completion, consuming GetResult, or repackaging it. The caller must consume it exactly once, including an already completed pooled source. Its original Faulted/Canceled status is preserved: an already Faulted operation containing OperationCanceledException is not normalized to Canceled by the framework. Pending consumption runs under the caller's usual await/context behavior.

Send routes requiring asynchronous Before, After, Exception, Finally, wrappers, or sessions retain their existing completion and context boundaries.

Stream uses the native typed cursor contract below, with new completion/context boundaries.

## Native typed Stream

A marked `IStreamHandler<TRequest,TItem>` returns an `IAsyncEnumerable<TItem>` through
Handle. Its Handle and GetAsyncEnumerator calls run on the first move, both with the
effective API/enumeration token. A null enumerable or cursor fails that move; failed
acquisition does not dispose an unacquired cursor. Each enumeration invokes Handle
again and owns its independent cursor. Selecting both source contracts for the same
request is ambiguous and is rejected.

A marked `IStreamSourceHandler<TRequest,TItem,TCursor>` opens one named cursor through
OpenAsync. Both input contracts retain the guarded owner and cleanup protocol below.
`StreamAsync(request, apiToken)` returns a generated class implementing
standard IAsyncEnumerable. `StreamSource(request, apiToken)` returns a readonly plan
that is not IAsyncEnumerable; its `ConsumeAsync<TSink>(sink, enumerationToken)` creates
a fresh private owner per consumption. It never aliases an owner acquired through
the standard enumerable. Both entries use the declared handler and stages. No Channel bridge,
independent producer task or compatibility backend is the default. Dedicated hooks
retain typed item flow; arbitrary IStreamMiddleware uses Stage.Wrapper and an explicit
IAsyncEnumerator boundary.

For standalone routes (one segment without opaque middleware), StreamAsync allocates
the source object before enumeration and reuses it as the first owner. Later
GetAsyncEnumerator calls create independent clones. That source also implements
IAsyncEnumerator; disposing it through that interface closes only the first owner,
and subsequent GetAsyncEnumerator calls still create independent clones. This cast
is not a common contract for every StreamAsync result.

With opaque middleware, the existing class enumerable adapter holds an immutable
plan and creates a new guarded cursor for each GetAsyncEnumerator call. The
standalone first-owner allocation therefore occurs even when no enumeration follows;
the opaque path keeps its source adapter and enumeration owners separate. Creating
either entry or acquiring an enumerator defers DI, opening, owned sessions and I/O
until that owner's first move. API and enumeration/terminal tokens link
lazily only when both are cancellable and different. A pending move must finish before
another move or disposal; overlap throws synchronously without stopping/joining it.
Pending disposal rejects moves and shares completion with repeated disposal. Current
is valid after true until the next accepted operation. Consume each ValueTask once.

Some Stream moves use reusable ValueTask sources. Operation readiness follows
completion of that source after owner state and required cleanup have settled;
it does not wait for an explicit AsTask conversion to publish its Task completion.
Another alias can therefore move or dispose the cursor, or access Current after
a successful move, before that conversion Task reports completion. Sequential
awaiting remains the supported usage. For a durable Task, call AsTask once and
reuse that Task without also consuming the original ValueTask. Its result remains
valid across later moves. Explicit AsTask conversion can allocate a bridge Task;
direct-await allocation characteristics do not extend to that conversion.

False filters loop to another guarded source move without publishing/prefetching an
item. The terminal awaits callbacks sequentially. False stops the operation normally
without retroactive cancellation; true permits the next token check. Consumer/sink
exceptions are not injected into source-side middleware. Cleanup runs once, releasing
owned cursors/sessions in reverse ownership order; cleanup failure wins under ordinary
try/finally. Borrowed services/provider/sink are not disposed. Keep the caller's scope
alive until enumeration/serialization and cleanup finish.

Middleware can reopen next only after normal inner EOF and completed cleanup. Failure,
early disposal or terminal false prevents restart. Partial explicit retries can
duplicate items; no automatic retry is added. Value-type sinks/cursor handles must not
copy mutable ownership accidentally. Internal ConfigureAwait(false) does not guarantee
UI context return and does not suppress ExecutionContext.

Stream follows ordinary C# call and await context flow. Creating a source does not
capture a request context for later replay. Synchronous callback changes to AsyncLocal
can reach following callbacks and, on a directly completed path, the caller. User
async methods retain their own context boundaries. Internal helpers are not an ambient
isolation contract, and synchronous and pending completion need not expose the same
ambient changes. Use request, cursor or session state for guaranteed data transfer.

Activation no longer isolates a synchronous Open from the first Move in a separate
helper. Code that derives items, filter decisions or exceptions from ambient changes
can therefore behave differently. Restore deliberately changed ambient values in
finally and balance Activity/log scopes around the awaited work they cover. A scope
opened only around Open does not cover later Moves. The framework does not suppress
flow, replay an owner-wide saved context, or deep-copy mutable HttpContext references.
Independent enumerations have independent ownership; keep request/DI scopes alive
until their operations and cleanup complete.

A segment containing an asynchronous Filter or Map runs source waits, ordered hooks
and rejected-item retries in one ordinary async move loop. A synchronous hook's
ambient changes can reach the next source pull after rejection. Synchronous source
changes are restored when that loop returns to outer cleanup or its caller, including
EOF and failure paths. Cleanup can therefore receive a different ambient value than
with the former separate source and publication helpers. User async methods retain
their own boundaries; keep resource identity explicit rather than recovering it from
an ambient value during cleanup.

The fused async frame can retain rejected input references across the next source
wait, so a long wait can prolong their lifetime. Representative checks observed
release after the operation settled and the cursor was disposed, but do not establish
a general retention bound. Allocation measurements using value-type items do not
measure the memory cost of retained reference graphs.

Standard enumeration, typed terminal and HTTP serialization are separate evaluation
paths. Evaluate each using the measured revision, conditions and results; typed
consumption does not guarantee lower time or allocation. A typed wrapper around an
erased external enumerable does not remove its inner iterator/promise work. See
[migration and full contracts](../streaming-0.5.0.ja.md).

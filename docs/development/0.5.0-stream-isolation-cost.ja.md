# Streamの隔離再現と有限costの実行案

C07の原計画1527行に残る隔離案の資料である。受入れ済みf080081の内部context境界照合とは分ける。BOCCHIが実ソースと限定案をレビューした後、CPU Colabで1 runを実行した。以下の実行案と期待列を保持し、末尾に実測結果と適用範囲を記録する。

## 対象と境界

参照request、int item、借用class service、同期F1→Map→F2、1要素、tokenなし、全同期完了の1形状だけを扱う。既存FallbackFixtureFor("int")の新reference、実生成canonical、実生成fusedと、追加した層別async iteratorの隔離controlを比較する。実生成canonicalは比較用の強制loweringであり、通常の選択優先度とpublic登録のZEN0037を変更しない。

隔離controlはHandler/source、F1、Map、F2の4層をasync iteratorで囲む。source層にguard、handler DI factory、Handle/GetEnumerator、Move/Currentとsource disposeを含める。item層は値が初めて届いた時点でguard、factory、同期callbackを同じ層内で呼ぶ。serviceは借用し、source cursorだけをdisposeする。cleanupの入口は記録するが、取消guardによってdisposeを省略しない。

これは旧stage別async境界の隔離を再現する実験モデルである。既存0.4.0のStreamRouteノード、DirectCall、struct continuation、pooling、startup/steady-state分離を再実装したものではない。0.4.0の実装全体との性能比較にも使わない。ExecutionContextのdeep copyではなく、共有objectへの副作用を巻き戻す仕組みでもない。

## 固定するtrace差

factory/H/Current/hookがAsyncLocalを再代入する。controlのguardも入口値を記録する。各Move/Disposeの返却時はcaller値を保ち、次Moveは新しいcaller値で始める。culture、SynchronizationContext、flow suppression、native pending、failureの新しい組合せは増やさない。

| 観測点 | 新reference／canonical／fusedの期待値 | 層別隔離controlの期待値 |
| --- | --- | --- |
| H／初回Current | factory:H | factory:H |
| F1 factory | getter | caller-first |
| F1 callback | factory:F1 | factory:F1 |
| Map factory | callback:F1 | caller-first |
| Map callback | factory:Map | factory:Map |
| F2 factory | callback:Map | caller-first |
| F2 callback | factory:F2 | factory:F2 |
| 次Move／source cleanup | caller-end | caller-end |
| consumerへの返却 | 各呼出caller | 各呼出caller |

controlの全event列はテストにliteralで固定した。新3系列は既存の新referenceへ完全一致を要求し、controlは同じ値[2]、副作用1回、source Current1回、Move2回、dispose1回と共通phase順を要求する。ambient差の一致は要求しない。これはまだ実測traceではなく、実行時に照合する期待列である。

## 最小cost計測

1 Factの意味論assertがすべて通った後に限り、環境変数ZENDIATOR_STREAM_ISOLATION_COST=1で有限cost処理を有効にする。既定は無効。traceを先にone-shape.jsonへ保存し、costが失敗した場合も意味論の証拠を残す。

costは同じint／参照request／借用class／F1→Map→F2の小さい手書きserviceを使い、新single-orchestration referenceと層別隔離controlの2系列だけを測る。実生成物のtiming系列は追加しない。1列挙で16入力をすべて通し、結果16個、checksum32、factoryとCurrent/hookのAsyncLocal再代入を維持する。値や処理量の差で速度を説明しない。

両系列64列挙ずつの固定warmup後、4 round、各系列512列挙を測る。順序はroundごとに反転する。各系列の実測列挙は2048回、全実測は4096列挙／65536入力。各ValueTaskのIsCompletedSuccessfullyを確認してからGetResultを1回だけ消費し、pendingが混ざったら停止する。時間はStopwatch ticks、割当はGC.GetAllocatedBytesForCurrentThreadの差を保存する。trace録画、dynamic compile、reflection、provider構築、delegate構築は計測外。DI解決、service/source/enumeratorの作成、guard、ambient変更、全列挙とdisposeは計測内。

この差にはiterator/state machineの数、guardの配置、DIを含む実行構造の差も含まれる。AsyncLocal隔離だけの純粋な単価ではない。別契約の局所cost資料としてns/列挙とbytes/列挙の生値を報告し、同契約の高速化率、0.4.0比、唯一の1c41d2b360件baseline、本体の採用判断へ転用しない。固定warmupはJIT/PGOの安定を証明しない。

## 一度だけの実行と終了条件

Release、SDK10.0.401/runtime10.0.12、Generator.TestsのこのFactだけを1 runする。CPU Colab1VMで環境、CPU、dotnet --info、固定source hash、DOTNET/TieredPGOの有効な設定を秘密を含めず記録する。local枠はSharpDepsにあり、許可が返るまで使用しない。既存のowned-process／Colab回収手順を使い、失敗後の自動修正・再実行をしない。

見込み240秒、全体上限600秒、remote上限420秒、回収／終了用120秒、cost区間は20秒で打ち切る。compile/generator失敗、extra/missing test、値/event/caller/回数差、同期完了条件違反、checksum差、timeout、所有process/sessionの終了不確認で停止する。TRX1、実consumer1、input/generated source/DLL、one-shape.json、finite-cost.jsonの8行、環境とsource pins、結果ZIPの読み戻しと所有終了を回収する。

1形状のtrace差、有限cost、適用範囲を文書化した時点で、この隔離資料を終了する。全context patternや追加測定群へ広げない。その後はC08の未達項目を小さい実装単位で進める。

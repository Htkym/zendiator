# C08の固定seedと共通event接続の限定案

この単位はC08原9.3の正準eventを、同期F1→Map→F2の既存reference／実生成canonical／fusedへ接続する。原C08全体の未達表は0.5.0-stream-c08-requirements.ja.mdに保持する。BOCCHIの実ソースレビュー後に、下記の固定条件で1 runを実行した。実行案を保持し、末尾にこの部分単位の結果を記録する。

## 固定する形状と入力

closed reference request、int item、借用class service、同期F1→Map→F2、API/enum tokenなし、full consumptionの1形状に限定する。既存FallbackFixtureFor("int")とCanonicalStreamItemReferenceを使う。comparison-only canonical loweringと通常のfused優先順位、public登録のZEN0037は変えない。製品C#差分は0。

generator version1、seed uint0xC0800500、xorshift32のshift13/17/5、値は(int)(state%9)-4とする。1本のstateからseed-4がdraw0〜3、seed-16がdraw4〜19を消費する。固定入力はPRNGを消費しない。順序とfailure位置を次の8ケースへ固定する。

| ID | 入力 | 生成情報／失敗位置 |
| --- | --- | --- |
| empty | [] | 固定、未起動hook |
| filtered | [-1,0] | 固定、Map/F2未起動 |
| single | [1] | 固定、出力[2]とcached Current |
| seed-4 | 長さ4、範囲-4〜4 | draw offset0/count4 |
| seed-16 | 長さ16、範囲-4〜4 | draw offset4/count16 |
| overflow | [int.MaxValue] | Mapのint変換overflow、F2未起動 |
| filter-failure | [1] | F1 callback、FormatExceptionの同一instance |
| factory-failure | [1] | F1 factory、InvalidOperationExceptionの同一instance、callback未起動 |

seed-4の固定列は[-2,4,-3,1]、seed-16は[-4,-2,3,-1,-3,-4,2,4,4,-3,1,2,1,2,-2,2]であり、同梱生成式の静的previewから期待値を固定した。テスト内でもこの列を照合する。これは実生成consumerの実行結果ではない。

既存probeのMapはlongで倍にしてintへConvert.ChangeTypeするため、overflowケースはその実際のnarrowing失敗を記録する。利用者のMap本体をchecked演算へ書き換えない。成功入力では宣言された演算から、値1だけが最終filterを通り、出力は2になるという性質も独立に確認する。

新しい1 Factが8ケースを順に処理し、各ケース3系列を実行する。pipeline実行24、reference対canonical／fused比較16、実consumer1、全入力26個／系列である。consumer Moveの回数は各入力長+1以下とする。生成器や失敗位置を無制限に増やすfuzz、全組合せ、追加のcontext／測定系列は含めない。

## 共通eventの意味

optional CanonicalEvent observerを既存FallbackProbeへ追加する。Resolve、HandlerStart、InnerMoveNext(sequence)、InnerCurrent(output)、Filter(stage/input/result)、Map(input/output)、Yield(output)、Throw(stage/exception identity)、InnerDisposeStart/End/Throwを、呼出しの発生位置または実際の成功／失敗が分かった位置で記録する。既存Traceの文字列解析や結果の事後推測でeventを補わない。

各eventはinvocation1、実際のrequest objectの同一性、token同一性、source sequence、typed int input/output、bool result、recorder内で安定した例外IDと型を持つ。requestが差し替わる／tokenが異なる／int以外の値が届いた場合はこの形状の違反として止める。pipelineが別requestを正当に差し替えるwrapperの仕様を否定するものではない。

factory失敗はDI factoryの実throw位置で記録し、callback未起動を確認する。filter失敗とMap overflowはcallback内でThrowを記録し、最終伝播例外が同じinstanceであることを確認する。source終了はdetachとcleanup後にMoveの失敗が外へ出る現在の意味に従う。callback成功eventを失敗時に捏造しない。

3系列は値、全event列、全操作status、source／factory／副作用の回数を比較する。同時にCurrent→F1→Map→F2→Yieldの順、F1 falseの後続未実行、lazy Resolve、Map副作用、source Current単読、consumer Currentのcache、失敗後の未起動hook、source dispose1回を確認する。Resolveにはこの単位のservice型roleと回数を記録し、service object identityや共有scopeの新たな検証は増やさない。

Move/Disposeは同期callsite throw、IsCompleted、IsCompletedSuccessfully、IsCanceled、IsFaulted、await結果／例外IDを別に保存する。ValueTaskは1回だけawaitし、status観測にGetResultを使わない。すべての呼出しは同期完了を要求し、予期しないpendingは差分として止める。source disposalのobserverはこの同期形状を対象とし、native/pending producerの終了eventを推測するものではない。

observerとfailure fieldは既定nullである。旧期待、旧reference本体、runtime emitter、APIの意味を変更しない。既済みのwrapper／context／token／open/value request／pending等のFactを、件数維持のために今回再実行しない。

## 単独再現と保存

既定では8ケースを実行する。環境変数ZENDIATOR_STREAM_C08_CASEを既知IDに設定すると、同じFactがその1ケース・3系列だけを実行する。同じassembly内ではinternalのReplayStreamSeedCase(ID)も同じ入口を呼び、外部からの単独再現は環境変数selectorで行う。未知IDは拒否し、他のpipelineや任意入力を実行しない。seed-16の再現でも先頭4drawを生成して同じoffsetを保つが、seed-4のpipelineは実行しない。

corpus.jsonにalgorithm/version/seed/生成順/draw offset/input全文/failure profile/selected IDs/件数を保存する。各系列のevents/操作status/回数を個別JSONへ先に保存し、3系列のcomparison.jsonも比較assert前に保存する。差分で止まった場合もpartial evidenceを保持する。再現する際は保存されたID・version・入力全文を同梱sourceと照合する。単独再現は入口の提供であり、失敗後の自動再実行を許可しない。

## 実行案と対象外

新1 Fact／固定8ケース／実consumer1／pipeline24／比較16を1 run、Release、SDK10.0.401/runtime10.0.12で実行する案である。通常runではcase selectorを空に固定する。CPU Colabとowned process枠を使い、見込み240秒、全体上限600秒、remote420秒、回収／終了用120秒とする。性能測定は0。local枠はSharpDepsのままで使用しない。

compile/generator failure、missing/extra Factまたはcorpus case、入力／seed順／event／status／値／例外同一性／回数差、予期しないpending、有限consumer上限超過、timeout、所有process/runtime終了不確認で停止する。修正、case除外、再試行を自動では行わない。成功時にTRX1、corpus8、branch JSON24、comparison8、input/generated source/DLL、環境とsource pins、結果ZIP読み戻し、所有終了を回収する。

この単位は同じ新契約・同じ1形状の観測を比較する。wrapper drop/gate/retry/複数open、別演算順、early break、cancel、native async/pending、DI scope/open/value request、culture/SC/suppression、nullable/large item、async item C10、type-changing/session C11、public／strict接続は対象外として原未達表と既存証拠を保持する。legacy finallyや任意wrapperの意味を書き換えて比較しない。C08全体や本体性能gateの完了をこの8ケースだけで宣言しない。

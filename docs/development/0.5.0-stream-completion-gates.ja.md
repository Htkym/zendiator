# C06/C07の完了条件とclosed候補の検証ゲート

原計画C06の完了条件はreference/value item、open/closed route、disposed scopeの適合である。第9.2節もopen generic requestを軸として挙げ、第18.2節はopen定義を保持してconsumer側の閉鎖を検証する。従ってopen適合を残件から消してC06全体の完了とすることはできない。一方、public generic dispatch methodの具体的なsignature形式は本計画では指定されていない。D02も最終public名/signatureは後続API設計で確定するとしている。

現在のopen service定義→closed request/item routeの閉鎖は、Handler属性で発見した定義をconsumer構成で閉じ、現行H01のPipeline/Handlers/Stageの型入力を検証する対応である。closed generic request/item、推定可能な型引数、代表constraints、両backendのDI解決に根拠がある。unbound request patternを構成modelとして保持し、任意の型引数で使える公開open routeを生成する対応とは区別する。この後者は、public API/登録形式と型parameter/constraint投影の依存が未解決であり、C06全体の残件として保持する。現在のclosed候補へ、その未確定public APIを追加することは今回の検証単位に含めない。

| 条件 | 現在の根拠 | 今回の代表確認／残件 |
|---|---|---|
| 型閉鎖・DI lifetime | ab9d525の15件。open service閉鎖、int/long/string、融合/canonical、lifetimeと全使用role override | 無変更の15件を再実行しない。open request pattern・full constraintsは残件 |
| lazy開始・借用scope | D02/D04契約、両emitterのfirst Move DIと到達時hook解決、借用serviceをdisposeしないcleanup | scopeをpending中に破棄した契約違反で、次DIが失敗し、owned cursorが終了する代表。安全なscope escapeは保証しない |
| canonical取消・OCE | CanonicalStreamFallbackEmitterのguard、単回await、async builder、detach/finally | API/enum pre-cancelと実pending取消、hook間遮断、foreign未取消OCE、cleanup置換とstatus/identity/token |
| linked ownership | 両token mergeとCloseのfinally | 非取消のGet失敗で、終了後のcancel伝播が切れる代表。既に取消されたtokenの即時callbackだけで解放を証明しない |
| wrapper境界 | C01、第8.4.1節。source→consumer順、typed lazy Open、outer request/token維持 | 同期direct passthrough／native async wrapperのcontext差分。既存5代表を全再実行しない |
| C07 | 第3.4/8.2.1節とD03。各Move/Dispose caller、通常のuser async境界 | canonicalの同期SynchronizationContext instanceとTask.Run suppression代表を追加。既存fused証拠からcanonicalへ保証を転用しない |

今回、上記closed候補のguard/status/wrapper/scope本体は既に生成コードに実装されている。実取消とcontextの未観測部分を確認するためのtest-only観測を追加する。原計画は全直積を要求せずpairwiseとリスク代表を要求しているので、全constraintsや全context組合せを今回の終了条件にしない。

C07は未確定public open routeや全shapeの適合を保証するものではない。複数wrapper、同時/再列挙Open、全context、非Microsoft provider、並行scope、session/値型receiver/aliasは後続の未確認範囲として残す。closed候補の代表確認をC06/C07全体の完了とは呼ばない。public採用と性能判断は別ゲートであり、ZEN0037とpublic登録遮断を維持する。

# Streamの型閉鎖と借用DI

C06の最初の実装単位は、closed request/item契約からopenなhandler／hook／wrapper service定義を閉じる前段である。`typeof(Handler<>)`や`Stage.Hook(typeof(Filter<>))`の型引数を、専用Stream interfaceのrequest/item型から推定する。暗黙のlocal Handler選択でも同じ閉鎖処理を使う。現在の型引数とconstraints判定には既存のGenericConstraintsを再利用する。

引数が全て決まらない、不一致、constraints不成立、複数の閉鎖候補がある場合は、closed serviceを明示するようsource location付きで診断する。open定義とclosed型の登録が同じ型へ閉じる重複も拒否する。閉鎖後の型は既存のfusion/canonical両backendへ渡し、fusion優先、public登録遮断、ZEN0037の境界を維持する。

DI resolverと実行templateは変更しない。Streamのenvelopeはproviderを借用し、handler／wrapperはそのcursorの開始時、hookは最初の到達時に通常のGetRequiredServiceで解決する。cursorが保持するhookは到達済みinstanceであり、transient指定を独立したsession stateとして扱わない。singleton/scoped/transientのinstance選択とfactory override、serviceのdisposeはproviderの責任である。生成cursorが所有して終了するのは取得済みsource cursorと自分のlinked tokenであり、providerやserviceをdisposeしたり暗黙のchild scopeを作ったりしない。

借用scopeは遅延実行と列挙中のservice利用より長く存続する必要がある。開始前にscopeを破棄した場合、列挙の開始時のDI解決失敗を返す。開始済みcursorを破棄済みscopeから独立したsessionへ変換する保証は追加しない。

この単位はopen service定義からclosed routeへの閉鎖であり、型引数を持つpublic open route methodの生成ではない。open request、open containing type、部分的な型閉鎖、constraints全組合せ、非Microsoft provider、並行列挙のscope利用、session／値型receiver／aliasは後続の依存として残す。C06全体の完了やpublic採用とはしない。実取消／OCE、複数wrapper、同時・再列挙Open、全context、性能の未確認範囲も引き継ぐ。

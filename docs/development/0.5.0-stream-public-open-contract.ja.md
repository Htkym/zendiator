## 適用前に判断する公開契約

IZendiator／ZendiatorとそのScoped登録は非genericのまま維持し、requestから型引数を推論できるgeneric methodを加えることを提案する。最初の成功fixtureに対する公開signatureは次の形である。Tは説明上の名前であり、実生成では既存bound型引数の対応を使う。

```csharp
IAsyncEnumerable<T> StreamAsync<T>(
    OpenAsyncRequest<T> request,
    CancellationToken cancellationToken = default)
    where T : class, new();
```

公開戻り値を固定intからそのrequestのitem型Tへ一般化し、handler／stageから合成した制約を公開methodにも同じく出す。違反するclosed consumerはC# compilerが拒否し、composition宣言の未確定／矛盾は既存source診断で拒否する。既存のclosed int overloadは変更しない。

同じ契約として、通常AddZendiator<Reads>の設定call site、marker namespace.Generated.Marker名、Scoped＋TryAddを維持する。handler／hookはopen定義をTryAdd登録し、公開methodから既存typed Create<T>へ薄く接続して、実行時にはH<T>とF1<Request<T>,T>／Map<Request<T>,T>／F2<Request<T>,T>の正しいDI keyへ到達する。既存登録は上書きしない。nongeneric registrarのsnapshot照合は、元宣言のtypeof(Request<>)、typeof(H<>)、Stage.Hook(typeof(F<,>))を使う。

この「非generic mediator＋requestから推論するgeneric method／可変item戻り値／合成制約」とopen Scoped＋TryAdd登録を、一体の最初の公開契約として受け入れるかが判断点である。新しいmode／Stableフラグや追加設定は提案しない。製品への適用はこの判断の後に行う。

BOCCHIはv11のこの公開契約を受け入れた。IZendiator／Zendiatorは非generic、公開methodの型引数・request／item型・where節はbound modelと同じ対応で生成する。class, new()はこのfixtureの合成結果であり、一般規則として固定しない。解除は同一item型・borrowed・単一pipelineのasync F1→async Map→sync F2に限定し、既存closed int入口を維持する。以下の最小実装・検証をこの機能単位で進める。

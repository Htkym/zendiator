原8.4.1／9.3の共通eventを、既存referenceと実生成canonicalのF1→W→F2へ接続する。BOCCHIの実ソースレビュー後、下記の固定条件で1 runを実行した。実行案を保持し、末尾に部分単位の結果を記録する。製品C#、reference本体、public登録、C10/C11、性能には変更を加えない。

## 固定する1 profile

IDはtwo-outer-saved-opens-drop-replace。入力[1,2]、参照request、int item、借用class service、同期item hookである。同じouter enumerableを順に2回列挙する。各outerのWは次を行う。

- 新しいItems(9)を1個作り、その同じinstanceで2回Openする。第一／第二Openは異なる未取消tokenを使う。両Openを保存してから列挙する。
- 第一上流はF1を通った最初の値1をdropし、breakして所有cursorを終了する。F2へは渡さない。
- 第二上流は[1,2]を最後まで処理し、W.Item→F2→consumerへ渡す。
- Wのfinallyは所有する上流が終了した後に記録する。outerのrequest／tokenをF2に保持し、Openの置換tokenを再びouter tokenと結合しない。

1 Fact／固定1 profile／実consumer1／reference・canonicalの2系列／比較1。各系列にouter2列挙、Open4回、source4実行がある。全体でouter4列挙、Open/source8実行。fusedはこのopaque Wの形状では候補にならず、wrapperを跨ぐ融合を比較用に捏造しない。

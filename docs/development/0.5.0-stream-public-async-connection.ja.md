# 0.5.0 非同期Stream hookの通常公開接続

2026-10-14。BOCCHIはLibrary v9の同期限定形状を受け入れ、同じclosed reference request／int／borrowed class／単一pipelineで、内部受入れ済みの非同期Filter／Mapの公開接続を指示した。v9の3同期列挙は成功証拠として再利用し、既存4テストの診断期待移行はcompile確認だけであり、再成功と数えない。

## 実宣言と接続範囲

実宣言はIAsyncStreamItemFilter<TRequest,TItem>.AcceptAsync → ValueTask<bool>、同一型のIAsyncStreamItemMap<TRequest,TItem>.MapAsync → ValueTask<TItem>、IStreamItemFilter<TRequest,TItem>.Accept → boolである。型変更mapの3型引数interfaceを流用しない。既存C10のAsyncItemFixtureSourceを使い、marker App.Reads、生成namespace App.Generated.Reads、通常AddZendiator<Reads>のcall siteをそのまま利用する。

今回の追加公開対象は、async Filter→async Map→sync Filterの3段に限定する。既存backendが選択したcanonicalの単一segment、closed／int／borrowed class／sessionなし／wrapperなし／同一item型を確認し、その既存Createへ薄く接続する。同期F1→Map→F2は元のprototype選択を維持する。public signature、Scoped＋TryAdd、既存登録の非上書き、dispatchでのnull検査、first Moveでのtoken／取消／開始、到達時hook resolve、既存cursorのcleanupとscopeの借用サービス所有を維持する。open／owned／型変更／wrapper／複数family等のZEN0037等は解除しない。

## 最小検証

新しい公開consumerを1回compileし、通常DIで生成IZendiatorを取得するtyped入口から、既存C10 probeのcompleted、pending-filter、cancel-mapの3列挙だけを行う。completedは非同期hookの同期完了、pending-filterは実pendingからMap／後続Filterへの到達、cancel-mapはMapの実pending中に取消し、F2の未解決とsource cleanupを確認する。未完了ValueTaskの単回消費、request／token、出力とcallback順序を確認し、cursor終了時にborrowed serviceを破棄せずscopeで終了することを照合する。独立referenceとのC10全6profileの再比較や既存matrixの再実行はしない。

同期成功形状はcompileだけで元prototypeと公開入口の生成を確認し、3同期列挙を繰り返さない。追加canonical分岐の拒否確認としてasync hookを含むwrapper形状を1回compileし、ZEN0037と公開出力なしを確認する。元結果、生成source／DLL、診断、TRX、実diff全文を既存Libraryへ保存して正確な版を読み戻す。時間HOLDと後日の最適化・再検証を保持する。測定／commit／push／Actionsは行わない。

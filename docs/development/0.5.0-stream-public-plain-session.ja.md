# 0.5.0 plain owned sessionの通常Stream公開接続

2026-10-14。v12＋v13の限定open公開接続の受入れ後、BOCCHIは内部受入れ済み列挙所有sessionを通常登録→公開StreamAsyncへ接続する単位を指示した。最初の範囲は既存SessionRuntimeSource(true)のclosed reference request／int、owned handler、owned Map→borrowed Map→owned Mapの単一plain pipelineとする。途中のitem型変更、wrapper、open session、複数familyは同時に広げない。公開signatureと生成App.Generated.ReadsのIZendiator／Zendiatorは既存closed int契約と同じであり、新API判断は不要である。

宣言はHandlerEntry.Session<SessionHandler,HandlerFactory>()、Stage.Hook<FirstSession,FirstFactory>()、Stage.Hook<BorrowedMiddle>()、Stage.Hook<LastSession,LastFactory>()。handlerと最後のhookのfactoryは同期IOwnedSessionFactory、最初のhookはIAsyncOwnedSessionFactory、session cleanupはIAsyncDisposableである。factoryとBorrowedMiddleはScoped＋TryAddでDIが所有し、session結果はcursorが列挙ごとに所有する。session結果をDIに登録しない。

公開登録用metadataへ既存HandlerFactoryと各Hook.Factoryを渡し、選択済みcanonicalのCreateへ薄く接続する。開始は最初のMoveで外側K2→K1→H、K1 factoryは実pendingである。正常終端後のsource／session保持とDispose、開始途中のH factory失敗時の取得済みK1→K2 cleanup、元例外保持は既存cursorを変更せず使う。factory callbackやcleanupの意味をpublic層で書き換えない。

新規1Fact、1consumer compile、public経路の再列挙2回とH factory失敗1回の合計3列挙に限定する。再列挙では同じenvelopeから6sessionの別instanceを確認し、失敗では2sessionだけのcleanup、source取得／handler開始0、元FactoryError instanceを確認する。両profileでfactoryとBorrowedMiddleのcursor破棄0／scope所有を確認する。正常のfactory3個＋borrowed middle1個、失敗の到達済みfactory3個をscopeで各1回終了する。既存reference比較・cleanup全matrix・v9〜v13成功runtimeや性能測定は再実行しない。元結果／生成source／実diff全文を既存Libraryへ保存・読み戻す。時間HOLDと後日の最適化・再検証、commit／push／Actions保留を維持する。

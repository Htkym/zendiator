# C11 generic・型変更・sessionのtyped統合

原8.10のsource item・最終item・各stage接続型の分離を、既存open request bindingとsession/wrapper segmentの共通typed loweringへ接続する。handler markerはsource itemを表し、最終itemはStreamPipelineの明示宣言である。既存generic overloadに加え、`StreamPipeline(typeof(Request<>), typeof(Final<>), ...)`で型パターンを宣言する。finalがopen definitionなら、最後の専用callbackの完全に束縛されたoutput型へ構造的に一致させて閉じる。Finalの型引数はそのoutput契約から決定する。request引数との名前・ordinal対応やbody解析で型関係を補わない。固定finalは従来通りnullable-awareに完全一致させる。

open receiver／factoryはliteral `HandlerEntry.Session(typeof(H<>),typeof(HF<>))`、`Stage.Hook(typeof(K<,>),typeof(KF<,>))`、Wrapperの同形overloadで明示する。request patternは選択済みhandler契約から導く。factoryの全引数はrequestと確定receiver型への専用factory契約のunificationで閉じ、各型の制約を同じopen bindingへ統合する。未決定引数・矛盾する制約はZEN0035、区間item不一致はZEN0026のErrorと該当source位置で拒否する。ref-like、open containing type、関係が決定できない形状を暗黙のobjectやruntime推測へ落とさない。

区間ごとのsource cursor・最終Current・hookのInput/Output・factoryのreceiver結果型を保持する。handler factoryはhandler区間だけ、wrapper factoryは各wrapper区間だけで取得する。既存の初回Move開始、独立cursor、単回ValueTask消費、所有分だけの逆順cleanup、DI所有service/factoryとowned/borrowed結果の分離へ接続する。新しいgeneric orchestration基盤やreference adapterを製品へ追加しない。public登録はZEN0037のままである。

有限検証は新1Fact・5入力。成功はopen request/service/factoryをclass/new制約で具体化してtyped finalへmapする1形状と、int→128-byte struct→wrapper/session→128-byte finalの1形状。拒否はfactory未決定引数、requestとの制約矛盾、wrapper区間型不一致の3入力のみ。consumer emit5、成功runtime consumer2、reference／生成DLLの外側4列挙・上流2列挙、合計6列挙・2比較。typed Currentと保持サイズ、factory結果・source型、選択cursor/state machineのitem box/unboxなし、owned session終了を確認する。128-byteはCurrentの保持型の大きさであり、総state size・allocation・JITコピーの測定ではない。

Release build1回・指定Fact1回。見込み240秒、総上限600秒、remote420秒、回収終了枠120秒。private CPU Colabを使い、local SharpDeps枠は使わない。重大な未決定仕様・初回失敗・timeout・pins/件数不一致・終了不確認は停止して返す。自動修正／再実行、追加profile探索、既済み取消／retry／cleanup失敗の直積は行わない。元結果・実diff全文・manifest・before・所有終了をLibraryに保存し実読み戻し後に最終レビューへ返す。

C11の意味論は、受入済み型変更の接続診断、plain/ wrapper session所有権、実pending cleanupと借用結果のDI所有分離に今回の2代表形状を対応付けて記録する。実証範囲を全generic/struct/任意wrapper列へ広げない。残る小規模allocation/timing、総allocation／JITコピー、採用判断・public解除は別の残件。commit/push/Actionsは保留する。

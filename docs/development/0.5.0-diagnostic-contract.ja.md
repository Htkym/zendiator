# 0.5.0 診断契約の現在地

N01の限定成果を記録する。現行35 descriptorはSG32件と局所lifetime Analyzer3件で、別descriptorの同一ID衝突を検査する。35規則すべての挙動を確認済みとは扱わない。

## 予約ID

| ID | 既存title | 現在の扱い |
|---|---|---|
| ZEN0014 | Unsupported notification erasure | ID・descriptorを保持した予約・非発火 |
| ZEN0019 | Ambiguous registration binding | ID・descriptorを保持した予約・非発火 |

現行のSG reporting経路に対応する発火箇所はない。`GenerationAnalysis.Error/ErrorAt`の呼出しは既存のliteral rule番号で、14/19を使わない。直接の`Rules` index参照とcanonicalのdescriptor選択にも該当経路はない。既存title以上の意図を推測して新しい拒否条件を追加しない。

## ZEN0020の防御条件

既存DI解析器は、実際のpackage bootstrapに解決された呼出しについて、Roslynの`GetInterceptableLocation`がnullならErrorを記録する。

```text
AddZendiator call cannot be connected to generated registration. Keep the call inside an ordinary method body.
```

Locationは呼出し全体のsyntax span。負例では次の二重括弧による呼出しを既存解析器へ直接渡す。

```csharp
((ZendiatorServiceCollectionExtensions.AddZendiator))(services)
```

コンパイラエラーがなく、括弧内はmember access、symbolはpackage由来のordinary methodであることを先に確認する。非interceptableなtargetはZEN0020を記録し、生成model/targetを返さない。通常の`ZendiatorServiceCollectionExtensions.AddZendiator(services)`はinterceptableで、診断なし・model/targetありとなる。この正負対照と全文・spanを既存`DiConfigurationTests`で固定した。

これは既存解析器の防御条件の検査である。現行public SGの発見条件はmember-accessの`AddZendiator`であり、この二重括弧targetを渡さない。public SG経由の新しい発火条件は追加していない。[RoslynのAPIとsyntaxによる制限](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.csharp.csharpextensions.getinterceptablelocation?view=roslyn-dotnet-4.14.0)も区別する。

## PackageReference consumerの受入れ

候補`682c64ac`の同一localpackを既存SDK10.0.401／10.0.112で使用した7 profileは限定受入れ済み。SDK・profile・NoWarnごとにrestoreからobj/bin/generated/SARIFを分離した。

代表ZEN0030では、準備時点はNoWarnを未実測としていた。現在は期待Errorによる非0終了と、NoWarn後のexit0・診断なしでもroute/compositionを生成しないことを別々に確認済みである。抑制を無効routeの適格化と扱わない。

読込み証拠はPackageReference、project.assets.json、隔離cacheのDLL hash、実生成・診断とSARIFである。Cscの直接引数ログを保存したとの保証は付けない。source-project直参照の成功をpackage読込みの代わりにしない。

## 測定と残件

44.1秒はpackage正しさ検証、8.6秒は3 process／6観測の記述的baseline取得時間である。baseline対象はSG＋compiler diagnostics＋Analyzerの合計で、consumer CLIのC#14とin-process Roslyn4.14 Previewは条件が異なる。初回と編集後を回帰率や改善率と呼ばず、Analyzer単独・IDE性能へ読み替えない。time/allocationの10%案は採用基準から除外した。

N01全完了は保留。exact SDK10.0.100最低host、IDEのload/性能、性能予算、その他規則の未受入message/location・正負仕様が残る。canonical lifetimeの適用範囲はN03へ分ける。現在のAnalyzerはGeneratedCodeAttributeを持つlegacy mediatorを認識するため、legacy fixtureの成功をcanonical split mediator全体の保証に広げない。

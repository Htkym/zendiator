# C10 async item hook 最小接続（実行前）

この変更は第3版8.9とC10の最初の部分実装である。既存typed canonical loweringに、同一item型の`IAsyncStreamItemFilter<TRequest,TItem>`と`IAsyncStreamItemMap<TRequest,TItem>`を接続した。新しい共通基盤や手書きpooling state machineは追加していない。公開登録は引き続きZEN0037で止まり、同期融合候補は同期hookだけを受け付ける。C10全体の完了や性能改善は未確認である。

## 契約判断

- 明示したStage.Hookの専用interfaceからcompletionをbindする。handler探索や任意Behaviorの書換えは追加しない。
- 宣言順に、既存cursorの`Move`内で各async hookの返したValueTaskを一度だけ`await ...ConfigureAwait(false)`する。`AsTask`や`IsCompletedSuccessfully`分岐、二重GetResult、WhenAllは製品側に追加しない。同期完了でもpendingでも同じ呼出箇所を使う。
- stage位置は生成コードの呼出箇所とコンパイラの再開位置で保持する。request、token、source、hook cache、処理中itemはawait metadataにも保持対象として記載する。refやref-likeをawait越しに保持する機能は追加しない。
- source Moveと各hookの直前にある取消チェックを維持する。今回の取消代表例はmap待機中にAPI tokenを取消し、mapを正常完了させ、次の同期filterの直前チェックでOCEを伝播する形である。hookがtokenを無視した場合の強制中断や、最後のhook完了後に新しい取消チェックを追加する仕様は導入しない。
- filter falseは次のsource Moveへ戻る。pending mapの結果は次の同期filterへ渡し、そのfilterがfalseならCurrentへ公開しない。
- 例外は既存MoveのcatchとCloseで処理する。source/linkをawait前に切り離し、cleanup例外が処理例外を置き換え、OCEのtokenとCanceled状態を自然に維持する。再Disposeでsourceを再終了させない。borrowed DIサービスの所有権とlazy resolveを維持する。
- pending中は既存busy guardにより次のMove/Disposeを拒否し、Currentを公開しない。この誤用応答はgenerated cursorだけで確認し、独立reference async iteratorとの同一性は主張しない。

## 限定検証案

新しい1Factが、consumerのSGコンパイルを1回だけ行い、下の6条件を各reference／actual generated canonicalの2系列で比較する。計12列挙、6比較である。referenceは通常のC# async iteratorで独立に記述し、generatorやIRのadapterを使わない。既存C08 retryの受入れ済み未commit差分4ファイルは変更しない。

| ID | 条件 | 主な期待 |
|---|---|---|
| completed | filter/mapとも完了済みIValueTaskSource | 値[2]、両GetResult各1、初回Move同期完了 |
| pending-filter | filter実pending、map同期完了 | 待機中map未解決、再開後[2]、各GetResult1 |
| pending-map | map実pending、結果4、後続同期filter false | F2へ4、公開値なし、item保持、各GetResult1 |
| filter-drop | filter実pendingからfalse | map/F2未解決、値なし、filter GetResult1 |
| failure-cleanup | map実pending失敗、source cleanupも実pending失敗 | cleanup同一instanceを最終catch、Faulted、source Dispose1 |
| cancel-map | map実pending中のAPI取消、map正常完了 | F2未解決、OCE token保持、Canceled、source Dispose1 |

全条件でrequest/token同一性、共通eventレコード全体、値、Move状態、実例外instance、source Start/Move/Current/Dispose、hook GetResult回数、lazy DI resolveを照合する。source Currentは1回だけ読み、公開Currentの再読はsourceを再読しない。pending開始とcleanup開始はTaskCompletionSource通知で待ち、AIや1ms timerの反復監視は使わない。製品async hook ValueTaskは既存ContractOnceの実IValueTaskSourceで単消費を検知する。

限定コマンドのfilterは`FullyQualifiedName=Zendiator.Generator.Tests.GeneratorTests.Stream_async_item_canonical_completed_pending_and_terminal_contracts_match_reference_once`。Releaseでbuild1回、test1回を提案する。既存Fact再実行、全件測定、性能測定は0。見込み240秒、総上限600秒、remote420秒、回収・所有process終了枠120秒。既存slotはSharpDepsのためlocal dotnetは使用しない。承認済みのprivate CPU Colab経路を使う場合も、このdiff／計画のBOCCHI実行前レビュー通過後に開始する。

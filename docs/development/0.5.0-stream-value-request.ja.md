# Streamのvalue requestと保持

原計画9.2の要求型matrixはvalue requestのboxing、制約、null timingを要求する。value itemの検証だけではこの条件を満たさない。D02は参照型requestを同じ参照で、値型requestを値で保持し、deep copyやbusiness objectのfreezeをしない契約である。この単位は通常のownableなstruct requestをclass handler/hook/wrapperで扱う内部候補を対象とする。ref-like requestや値型receiver全体の採用を追加しない。

既存の型対応とgraphはvalue requestを表せるが、Streamのfusion/canonical projectionがRequestIsValueTypeで候補を止めていた。emittersのCreateとcanonical wrapperのUpstream.Openは無条件でArgumentNullException.ThrowIfNull(request)へrequestを渡していた。これを値型に用いるとobjectへの変換でrequestをboxする。今回はrequestの遮断を外し、value requestにこのnullチェックを生成しない。servicesのnullチェック、reference requestの同期nullエラー、HandlerIsValueType/HookIsValueType/WrapperIsValueTypeによるreceiver遮断は保つ。

## コピーと保持の判断根拠

| 境界 | 既存の生成形状と意味 |
| --- | --- |
| Create | 型付きrequestを値渡しで受け、envelopeの型付きfieldへ保持する。callerの後のstruct field変更を読む契約ではない。 |
| GetAsyncEnumerator | envelopeの保持値を新cursorへ渡す。cursorも同じ具体request型のfieldを持ち、各列挙の状態は独立する。 |
| fusion RunSegment | 型付きrequestをasync iteratorへ渡す。compiler生成state machineも型付きで保持する。 |
| handler/filter/map | 各専用interfaceの引数はTRequestの値渡し。service receiverをinterfaceで呼んでも、requestをIStreamRequest/objectへ変換する必要はない。callbackのstruct field書換えは次のcallbackへ伝播しない。 |
| wrapper/upstream | wrapperに渡すrequestは値渡し。wrapperが変更したlocal値でOpenした場合、その値を上流envelope/cursorが保持する。外側のdownstreamは外側の保持値を使う。 |
| request内の参照field | structのコピーでも同じbusiness objectへの参照を保持する。参照先の変更は可視であり、deep freezeをしない。 |
| DI | providerはclass serviceをobjectとして返す。これはserviceの解決境界であり、request boxingの要求ではない。service/providerをcursorがdisposeしない。 |

表はC#の値渡し・field保持と観測可能な意味を示す。JITのcopy elision、register spill、物理的なコピー回数/bytesを断言しない。envelope/cursor/iterator等のobject生成、async builder、ユーザーbody、reflection harnessのboxingを含む全割当0を意味しない。既存のDirectCall/struct continuation/poolingを別の新規改善として数えない。

## 必要最小の検証

新規8件を提案する。closed struct/int fusion、closed struct/long canonical（最初のMoveで実pendingを作る）、open structをint/stringで閉じるgeneric canonical、struct wrapperの置換値とearly break、default struct＋開始前disposed scope、reference requestのnull timingをfusion/canonicalで確認する。有限の大きなrequestは6つのlong、Marker、Value、共有参照fieldを持ち、実際のUnsafe.SizeOfを結果へ保存する。

実生成source/DLLをcompileし、生成候補とcompilerの子型に限定してILを読む。request型へのbox命令、型付きrequest field、型付き引数のcall/constructorを記録する。reflection/Activatorでrequestをboxするtest harnessとユーザーbodyはこのIL判定の範囲外である。static sourceだけで「request boxingなし」を結論しない。

runtimeではCreate後にcallerのboxed test入力のMarker/Padを書き換え、生成経路がCreate時の保持値を使うことを確認する。handler/hookも自身の値渡し引数を変更し、他callbackのMarkerが変わらないことを確認する。同時に共有参照fieldの変更は見えることを確認し、再列挙でも保持値と参照の意味を維持する。wrapperは変更したlocal値を上流へ渡し、外側downstreamが外側値を使うことを確認する。reference oracleとの比較は値/観測順/DI/owned source終了の意味を対象とし、oracleのnull-check boxingを総割当比較へ混ぜない。

class serviceはscoped factory overrideで解決し、初回到達まで未解決、2列挙でもscope内4serviceを借用する。source cursorを列挙毎に終了し、serviceの終了はscopeへ委ねる。default structはframework Createで拒否しない。user handlerによるbusiness field検証は変更しない。reference requestのnullは従来どおりCreateで同期throwし、ParamName=requestを維持する。

この差分は実行前の候補である。public登録/ZEN0037を保ち、速度改善を主張しない。C06/C07全体、全value request/contextの組合せ、全constraints、値型receiver、ref-like/alias、他provider、public採用/性能は後続条件である。sessionは原計画C11の後続とし、このvalue request単位の先行ブロッカーにしない。次はC07のfactory/callback/downstream context境界を原要件へ照合する。
